# ABCD 初始化技能包

本包沿用原项目initialization的目录、九份文件及分工方式，项目改为智能客服系统。共同大纲v1.1是初始化建议，由四人共同敲定；具体服务业务、知识资料、原型范围和业务决定按实际记录。

所有成员先完整阅读[共同大纲](共同大纲.md)、[协作协议](协作协议.md)、[文档格式规范](../docs/文档格式规范.md)及[提交要求对照](../docs/提交要求对照.md)，共同确定章节、图表、篇幅和分工，再读取本人的skill执行。

| 成员 | 入口 | 主要职责 |
|---|---|---|
| a | [req-a-spec/SKILL.md](req-a-spec/SKILL.md) | 第1章、第2章业务及第4章；来源、用例、规则与权限 |
| b | [req-b-model/SKILL.md](req-b-model/SKILL.md) | 第3、5章及主要模型；对象数据、状态与协作 |
| c | [req-c-prototype/SKILL.md](req-c-prototype/SKILL.md) | 2.5/2.6、第6章、7.3与原型；质量报告汇编、索引和合并导出 |
| d | [req-d-verify/SKILL.md](req-d-verify/SKILL.md) | 7.1/7.2/7.4、第8章；验收覆盖、独立复核及AI报告 |

## 规模与落地

共同大纲v1.1已收敛为适合四人完成的首版：知识库咨询、知识维护、基础工单及记录反馈。经费是可行性考虑，不设固定30元上限。优先验证外部模型API和简单检索，技术选型以实际问题为依据；阶段原型服务于后续真实实现，不默认要求商业平台规模。

## 使用

入口是本文件，先读共用材料再读本人角色。当前包只有规则、职责与文档规范，不包含既定业务、模型、原型或验证结论；实际产物按共同确定的最小目录逐步建立。

不要求特定agent工具或自动安装。工具能读取仓库文件时，直接指定上述相对路径；不能识别skill格式时，把对应文件作为初始化上下文。单独复制一个角色目录时，要同时提供共用大纲、协议及格式规范。

可向agent发送：

> 项目是智能客服系统。先读initialization/skills/共同大纲.md、initialization/skills/协作协议.md、initialization/docs/文档格式规范.md、initialization/docs/提交要求对照.md及本角色SKILL.md。检查已有共同决定，没有决定的部分先提出讨论事项。资料按本轮实际搜集情况登记出处；按角色职责逐步更新文档，完成后给出文件、变更、待决和下游交接。Git操作按本轮授权执行。

初始化包规定工作方式，不预设客服业务规则、类名、图形内容、测试数据或结果。实践产物在实际工作发生后建立。

四人分别指定角色入口：a读req-a-spec，b读req-b-model，c读req-c-prototype，d读req-d-verify。先同步已有文件和决定，再在本人职责内更新正文；每批交接文件、输入/输出版本、未决项、证据及接收者。产品中的AI答复与成员使用agent完成作业分别记录。
